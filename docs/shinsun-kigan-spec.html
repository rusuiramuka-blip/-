新春祈願受付管理
実装仕様書

久留米成田山「新春祈願受付管理｜信者様・会社」の実装仕様です。設計案 v0 と、第1回〜第5回の確認で得た 20 件の決定を1つにまとめました。この仕様書の承認を得てから実装に着手します。現時点でスプレッドシート・数式・Apps Script・Google フォーム・トリガー・共有設定の作成／変更／削除、およびメール送信は一切行っていません。

決定事項の一覧

#論点決定
①区分の切り方属性で分ける。90_信者様マスター と 91_会社マスター。前札／新春一般は申込側の属性
②住所・電話・メールの正本この管理表。らくまる寺務からの取込は行わない
③祈願札区分・願意現行「祈願申込入力」と共有（9区分・38願意）。正式名称。コピーで持つ
④移行する過去年度R2 前札マスター＋読上げ名簿 2023／2024／2025。R9 から新台帳
⑤信者様の案内単位個人単位。世帯IDは一括領収書・同封の単位
⑥会社の本社・支店分ける。会社ID＋拠点ID
⑦Google フォーム前札用・新春一般用の2本
⑧奉納品・授与品94_明細 に含め、数量と金額を管理
⑨前札の祈願形態元朝の一斉読上げ＋希望者は個別枠も取る
⑩祈願枠30分刻み。1枠に複数組
⑪フォームの範囲新規の方も受け付ける
⑫領収書・請求書要望があった場合のみ発行（既定値は不要）
⑬案内状10月に対象生成、11月に郵送。一括差込印刷
⑭郵送料寺院負担。祈願料に含む。送料の列は持たない
⑮翌年度の案内停止明確な理由のみで停止。未申込は外さず要確認
⑯トリガー所有年間法会受付管理と同じ管理用アカウント
⑰枠の対象日・時間帯1/1〜1/31、9:00〜16:00
⑱1枠の上限人数 50 名・組数 3 組（超過は要確認、登録は止めない）
⑲未申込要確認年数3 年
⑳御札の種類外札・内札（＋新春一般用に 一般札 を1種）

⑳の補足。第5回で選ばれたのは「外札・内札（前札）」のみでしたが、それだけだと新春一般（五千円〜三万円）の御札種別が未定義になります。98 に 一般札 を1種追加します。木札・紙札・角札・交通安全札は沖縄の実績にのみ現れ、久留米の資料には出てこなかったため入れません。必要になれば職員が 98 に追記できます。

設計上の決まり

  • 固定列番号に依存しない1行目の見出し名から列を解決し、見出しは 00_定数.gs に定義します。
  • 年度・料金・時間枠・フォームID・外部ファイルIDをコードへ埋め込まないすべて 99_設定 から読みます。
  • 読み書きは一括getValues()／setValues() で範囲をまとめ、1行ずつのループで台帳を読み直しません。
  • onOpen はメニュー表示と受付画面の更新だけシート構成の修復・全件再集計はしません。
  • onEdit で全件再集計しない編集された行に関係する範囲だけを更新します。
  • 新しい内容を作ってから書き換え、余った旧行だけ消す途中エラーでデータが消えないようにします。

受信処理

フォーム送信
  ↓
96_フォーム受信 へ原文を保存        ← ここで失敗しても原文は残る
  ↓
回答IDで 93 を検索
  ├ 既存あり → 何もしない（二重登録・二重入金・二重メールを防ぐ）
  └ 既存なし → 続行
  ↓
案内IDあり → 92 の既存行に紐付け
案内IDなし → 92 に「フォーム新規」の行を生成
  ↓
90/91 に対象が見つかるか
  ├ 見つかる   → 対象IDを設定
  └ 見つからない → 仮ID＋要確認「マスター未登録」
  ↓
93 を 申込状態＝受付中 で作成 → 94 の明細を生成
  ↓
氏名・電話・住所の一致で重複候補を検出 → 通知のみ（登録は止めない）

確定 にするのは職員です。フォームからの申込が自動で確定になることはありません。

トリガーと診断

トリガー種類対象

  • すべて年間法会受付管理と同じ管理用アカウントで作成します。
  • 「設定状態を確認」は上記4本の件数・種類・対象IDを照合し、インストール型トリガーは作成者アカウントごとに管理される旨を画面に明記します。
  • 復旧関数は「不足分をすべて作成できてから、不要・重複・種類違いを削除」の順序。作成途中で権限エラーが出ても既存の正常なトリガーが残ります。
  • 復旧後に4本の状態を再検証し、期待値と合わなければ例外を投げます。

手順

  • 元ファイルは一切変更しない。読み取り専用で 97_移行作業 へ書き出す。
  • 97 には元ファイル名と元の行番号を付ける。
  • 職員が 97 で分類する（下記）。
  • 分類後、97 から 90／91／92／93／94 へ反映する。
  • 件数照合：移行元の行数・移行後の行数・除外した行数と理由を 99 のログに残す。
  • 過年度の 92 は参照専用。案内状態は （過去実績） で固定し、再生成の対象にしない。
