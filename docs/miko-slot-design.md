# 枠先行・自己エントリー運用の設計

「仮枠を先に置く」「本人が入る」「足りないところが一目でわかる」「実働が違ったら直せる」の
4 つを、いまのシートの上に載せる形での設計。`07_必要人数` と `04_日別30分配置` に
必要な部品はすでに揃っているので、作るのは **枠の自動生成・巫女用ウェブアプリ・
期間サマリ・当日ボタン** の 4 つ。

## 起点となる数字（現ファイルの実数）

| 項目 | 値 | 出どころ |
|---|---|---|
| 1日あたり必要人数 | **42**（早番20・中番20・深夜2） | `07_必要人数` 使用23定義 |
| 登録スタッフ | 36名（社会人20・高校生16） | `01_スタッフ` |
| 18歳未満 | **11名** | `01_スタッフ!F` |
| 作成済みの枠 | 138行（12/29〜1/1 の4日のみ） | `02_シフト入力` |
| 仮枠（担当者なし） | **0** | `02_シフト入力!D` |
| 対象期間 | 2026/12/29〜2027/1/31（34日） | `_設定!B2・D2` |

**いまは枠先行がまだ始まっていない。** 138行すべてに担当者名が入っていて、
巫女が入る余地のある仮枠はゼロ。`00_ホーム` の「未割当枠 0」はその意味で、
「配置不足 93」は 1/1 の `04_日別30分配置` だけを数えた値。

### 時間帯の定義

| 時間帯 | 時刻 | 必要人数 | 備考 |
|---|---|---|---|
| 早番 | 8:00 – 14:00 | 20 | |
| 中番 | 14:00 – 19:00 | 20 | |
| 深夜 | 23:00 – 翌8:00 | 2 | 日跨ぎ。**18歳未満は不可**（労基法61条） |

23定義すべて「対象日」が空欄＝期間共通。特定日だけ増やす行を足せば上書きされる作りは
そのまま使える。

## 誰が何を見るか

「運用が簡単」は機能を減らすことではなく、**役割ごとに見る場所を1つに絞る**ことで作る。
現状は現場メニュー9項目・管理メニュー11項目が全員に見えている。

| 役割 | 見る場所 | 操作 |
|---|---|---|
| 巫女 | スマホのウェブアプリだけ | 空き枠を見て「入る」。スプレッドシートは開かせない |
| 現場担当 | `02B_募集状況` / `04_日別30分配置` / `02A_当日勤怠` | 枠を足す・当日の並びを見る・実働を確定。メニュー4つ |
| 管理者 | 給与ファイル | 承認→締め→支給→受領。メニュー5つ |

## ① 枠を先に作る

`07_必要人数` から `02_シフト入力` へ、担当者を空欄にした行を必要人数ぶん自動生成する
メニューを作る。

```
// 07_必要人数（状態="使用"）× 対象期間の各日 → 02_シフト入力
生成する列    B 日付 / F 出勤 / G 退勤 / H 休憩分 / J 主配置 / K 賃金区分 / N 状態="下書き"
空けておく列  D 担当者   ← ここに巫女が自分で入る
自動で埋まる列 A 勤務ID / C シフト名 / E スタッフID / I 実働予定 / L 昼食 / M 夕食
              P 警告 / S 開始日時 / T 終了日時 / U 深夜予定h

対象日の決め方（既存の 04_日別30分配置 と同じ考え方）
  その日を指定した行があれば → その行の必要人数
  なければ                  → 対象日が空欄の行（期間共通）の必要人数

再実行しても増えない
  「日付 × 配置 × 時間帯」で既存の枠を数え、不足ぶんだけ追加する
```

深夜枠は 23:00→翌8:00 で退勤 < 出勤になるが、既存の `T 終了日時` の式が
`IF($G<=$F,1,0)` で翌日補正しているのでそのまま動く。休憩分の既定値だけ決めること。

> **行数の拡張が前提条件。** 42名/日 なので正月三が日前後の6日間でも252行、
> 34日全部なら1,428行。`02_シフト入力` は現在5〜504行の**500行**しかなく12日分で満杯。
> 先に3,000行程度へ拡張し、数式の参照範囲（`$B$5:$B$504` など）も同時に伸ばす。

## ② 巫女が自分で入る

> **スプレッドシートを巫女に共有してはいけない。**
> `01_スタッフ` には全員の区分・18歳判定・襦袢の貸与状況が並び、`02_シフト入力` は
> 誰でも他人の行を消せる。閲覧権限だけでも個人情報が全部見える。

代わりに **Apps Script のウェブアプリ**（実行者＝管理者、アクセス＝Googleアカウント
所有者全員）を1枚作る。巫女はスマホでURLを開くだけで、スプレッドシートには触れない。
書き込みは管理者の権限で行われるので共有設定を変える必要もない。

### 画面

- 日付を選ぶ → その日の 早番/中番/深夜 が残り人数つきで並ぶ（「早番 あと8人」）
- 「入る」を押す → 確認 → 完了。自分の枠には「入っています／取り消す」
- 足りない日は赤、あと少しは黄。`02B_募集状況` と同じ色にすると
  「赤いところに入ると助かる」が言葉なしで伝わる

### 本人の特定

`01_スタッフ` に **メールアドレス列（I列）** を追加し、ウェブアプリ側で
`Session.getActiveUser().getEmail()` と突き合わせる。登録のないアドレスは弾く。
合言葉方式より安全で巫女側の手間もない。

### 安全弁 — 自己申込にするならここが本体

- **18歳未満は深夜枠を選べない** — `01_スタッフ!F` が「18歳以上」でなければ深夜枠を
  非表示にし、送信時にもう一度弾く。労基法61条。登録36名のうち11名が該当するので
  人手で見張るのは現実的でない
- **時間が重なる枠は取れない** — 開始日時・終了日時の重なりで判定。これで
  「同日複数勤務」の警告が本当に重なっているときだけ出るようになり、早番＋遅番の
  分割勤務が毎回警告になる現状の問題も同時に解決する
- **定員に達したら締切** — `LockService.getScriptLock()` の内側で残数を数え直してから
  書き込む。ロックを取らずに書くと正月の申込ラッシュで必ず定員オーバーが起きる
- **直前の取消は本人にさせない** — 前日18時以降は「取り消す」を出さず現場への連絡を促す。
  取消希望は `09_申込` に記録だけ残す
- **1人あたりの上限（任意）** — 連続勤務日数や合計時間の上限を `_設定` に置く

### 書き込みの作法

```
// 追記専用の監査ログ（新シート 09_申込）
申込ID / 送信日時 / スタッフID / 氏名 / 勤務ID / 操作(申込・取消) / 結果(確定・定員超過・不可) / 理由

// 02_シフト入力 への反映（ロックの内側で）
D 担当者   ← 氏名
R 更新日時 ← now
Q 給与連携 ← '未送信'   // ← 忘れやすい

※ スクリプトによる書き込みでは onEdit（簡易トリガ）が発火しない。
   R・Q はウェブアプリ側で明示的に書く必要がある。
```

申込をいったん保留して管理者が確定する「承認モード」にしたい場合も、`09_申込` に
「受付」で止めて別メニューで確定するだけ。切替は `_設定` のフラグ1つ。
経験者の配分を調整したい日だけ承認モード、というのが現実的。

## ③ 一目で足りないところがわかる

不足を出す計算は**すでに `04_日別30分配置` の 61〜73 行にある**。
「割当済／枠／必要」を出して `不足 / 未割当 / 適正 / 余剰` に振り分ける、よくできた式。
問題は見え方のほう。

- **1日ずつしか見えない。** B2 で日付を切り替える作りなので、34日間のどこが足りないかは
  34回切り替えないとわからない
- **13配置 × 48列 = 624セル**を目で追うことになる。1/1 だけで「不足」が93セル
- **52枠の表示上限**があり（`A58` の警告）、42名/日 に交代が入る 1/1 は超える

### 新シート `02B_募集状況` — 期間ぜんぶを1画面に

行＝日付、列＝時間帯。セルは「あと何人」。34行 × 5列なのでスクロールなしで収まる。
実データを置くとこう見える。

| 日付 | 必要 | 枠 | 確定 | あと | 状態 |
|---|---:|---:|---:|---:|---|
| 12/29 (火) | 42 | 34 | 34 | **8** | 枠を8つ追加 |
| 12/30 (水) | 42 | 34 | 34 | **8** | 枠を8つ追加 |
| 12/31 (木) | 42 | 49 | 49 | +7 | 必要より7枠多い |
| 1/1 (金) | 42 | 21 | 21 | **21** | 半分しかない |
| 1/2 (土) | 42 | 0 | 0 | **42** | 枠が未作成 |
| 1/3 (日) 〜 1/31 | 42 | 0 | 0 | **42/日** | 枠が未作成（29日分） |

必要・枠・確定はいずれも現在のシートの実数（時間帯ごとの内訳は枠を生成した時点で決まる）。
この1枚があれば「1/1 が半分しか埋まっていない」「1/2 以降は枠すら作っていない」が
最初の3秒でわかる。いまは同じことを知るのに `04_日別30分配置` の日付を34回切り替える必要がある。

### セルの式（考え方は既存の `B61` と同じ）

```
=LET(
  d, $A6, band, B$5,
  // その日を指定した行があればそれを、なければ期間共通を使う
  spec,    SUMPRODUCT(N(必要!$B=d), N(必要!$E=band), N(必要!$K="使用"), N(必要!$H)),
  hasSpec, SUMPRODUCT(N(必要!$B=d), N(必要!$E=band), N(必要!$K="使用")),
  gen,     SUMPRODUCT(N(必要!$B=""), N(必要!$E=band), N(必要!$K="使用"), N(必要!$H)),
  need, IF(hasSpec>0, spec, gen),
  // 担当者が決まっている枠を数える
  filled, COUNTIFS(シフト!$B, d, シフト!$V, band, シフト!$D, "<>", シフト!$N, "<>取消"),
  need - filled)
```

> **前提：`02_シフト入力` に「時間帯」列（V列）を足す必要がある。**
> いま `C シフト名` は出勤時刻から **早番／中番／遅番** を出すが、`07_必要人数` の
> 呼び名は **早番／中番／深夜**。この2つが食い違っているため時間帯での突き合わせが
> そのままではできない。`07_必要人数` 側の呼び名に統一し、V列で開始・終了時刻から
> 時間帯名を判定する。

### 2つのシートの役割分担

| シート | 粒度 | 使う場面 |
|---|---|---|
| **02B_募集状況**（新） | 日 × 時間帯 | 募集を出すか、枠を足すかの判断。巫女への声かけ |
| **04_日別30分配置**（既存） | 配置 × 30分 | 当日の並び。どの売場が何時に薄いか |

## ④ 実働が予定と違ったとき

`02A_当日勤怠` は予定と実績を分けて持ち、差異区分・実働差分・変更理由・元勤務IDまで
用意されている。設計は正しいので、**足りないのは操作を1タップにするボタン**。
`00_ホーム` にも「メニューの『予定どおりを反映』が最短です」と書かれているが、
そのメニューはまだ存在しない。

| 実際に起きたこと | 操作 | 起きること |
|---|---|---|
| 予定どおり働いた | **予定どおりを反映** | 実出勤・実退勤・実休憩に予定をコピー、実績状態＝勤務済。複数行まとめて |
| 遅刻・早退した | 実出勤／実退勤を直すだけ | 差異区分・実働差分（M列）が自動で出る |
| 休憩が違った | 実休憩を直すだけ | 同上 |
| 当日欠勤 | **欠勤にする** | 実績状態＝欠勤確定、変更理由を必須入力、給与は0 |
| 前日までに取消の連絡 | **枠を再募集する** | 担当者だけを外す。**枠は残る**ので 02B に「あと1人」として戻り、他の巫女が入れる |
| 代わりの人が入った | **担当者を交代** | 元の行を取消、新しい勤務IDの行に元勤務IDを記録 |
| 途中で売場が変わった | `03_配置変更` に追記 | `04_日別30分配置` に反映（既存機能） |

> **枠先行でいちばん大事な区別。** 欠員が出たとき `02_シフト入力` の行を「取消」に
> してはいけない。行ごと取消にすると**枠そのものが消えて募集に出なくなる**。
> 外すのは担当者（D列）だけ。`00_ホーム` の未割当枠の式が `状態<>取消` を条件に
> しているのは、まさにこの区別のため。

実績が固まったら `02A_当日勤怠` → 給与ファイルの `01_勤怠承認` へ送信する。
この送信処理は診断の A-2 で挙げたとおり**まだ実装されていない**。
ここが繋がって初めて、現場の1タップが給与まで通る。

## ⑤ 毎日の画面を1枚にする

`00_ホーム` を「その日に手を動かすこと」だけに置き換える。

| 区分 | 表示 | 押すと |
|---|---|---|
| 今日 | 出勤予定 n 名 | 04_日別30分配置（今日） |
| 今日 | 実績が未入力 n 件 | 02A_当日勤怠（該当行） |
| 募集 | 不足が大きい日 上位3日 | 02B_募集状況 |
| 募集 | 枠が未作成の日 n 日 | 「期間の枠を作成」を実行 |
| 給与 | 未送信の実績 n 件 | 「実績を給与へ送信」を実行 |
| 給与 | 要対応の警告 n 件 | 08_管理チェック |

- 各行から `HYPERLINK` で該当シートへ飛ばす。どこを開けばいいか毎回考えなくて済む
- エラーは日本語で `ui.alert` に出す。メニュー関数を `runSafely_` でくるみ、
  Apps Script の英語の例外画面を出さない
- 巫女向けの案内は1枚だけ。ウェブアプリのURLとQRコード、締切のルール、それだけ

## 進め方

診断で挙げた **A-1（スタッフIDの列違い）** と **A-3（襦袢台帳の列違い）** は
定数の付け替えだけなので、どの段階よりも先に直しておくと以降が楽になる。

| 段階 | やること | この時点でできるようになること |
|---|---|---|
| 0 | 診断の A-1・A-3、行数の拡張 | 送信したデータが給与側で正しく紐づく |
| 1 | V列（時間帯）追加、呼び名の統一、**02B_募集状況** | 34日分の不足が1画面で見える |
| 2 | メニュー「期間の枠を作成」 | 仮枠が並ぶ。手で138行入れる作業がなくなる |
| 3 | ウェブアプリ（18歳未満の深夜ブロック・重複判定・ロック） | 巫女が自分で入れる。02B の赤が減っていく |
| 4 | 当日ボタン4つ ＋ 実績を給与へ送信 | 現場の1タップが給与まで通る |
| 5 | 00_ホームを「今日やること」に、メニューを役割別に整理 | 毎日開く場所が1つになる |

段階1と2だけでも「1/2 以降は枠すら作っていない」状態は解消できる。
ウェブアプリ（段階3）は作る量が最も多いので、正月に間に合わないようなら段階2までを
先に入れて**枠の一覧を印刷して手挙げしてもらい、現場担当が入力する**運用でも回る。
その場合でも 02B があるかないかで募集のかけ方が変わる。
