# 新春祈願受付管理｜実装仕様書 v1.0（確定版）

久留米成田山「新春祈願受付管理｜信者様・会社」の実装仕様。
設計案 v0（`docs/shinsun-kigan-design.md`）と、第1回〜第5回の確認で得た決定を1つにまとめたもの。

> **この仕様書の承認を得てから実装に着手する。** 現時点でスプレッドシート・数式・
> Apps Script・Google フォーム・トリガー・ファイル・共有設定の作成／変更／削除、
> およびメール送信は一切行っていない。

---

## 1. 決定事項の一覧

| # | 論点 | 決定 |
|---|---|---|
| ① | 区分の切り方 | 属性で分ける。`90_信者様マスター` と `91_会社マスター`。前札／新春一般は申込側の属性 |
| ② | 住所・電話・メールの正本 | この管理表。らくまる寺務からの取込は行わない |
| ③ | 祈願札区分・願意 | 現行「祈願申込入力」と共有（9区分・38願意）。願意は正式名称。コピーで持つ |
| ④ | 移行する過去年度 | R2 前札マスター＋読上げ名簿 2023／2024／2025。R9 から新台帳で運用 |
| ⑤ | 信者様の案内単位 | 個人単位。世帯IDは一括領収書・同封の単位 |
| ⑥ | 会社の本社・支店 | 分ける。会社ID＋拠点ID |
| ⑦ | Google フォーム | 前札用・新春一般用の2本 |
| ⑧ | 奉納品・授与品 | `94_明細` に含め、数量と金額を管理 |
| ⑨ | 前札の祈願形態 | 元朝の一斉読上げ＋希望者は個別枠も取る |
| ⑩ | 祈願枠 | 30分刻み。1枠に複数組 |
| ⑪ | フォームの範囲 | 新規の方も受け付ける |
| ⑫ | 領収書・請求書 | 要望があった場合のみ発行（既定値は不要） |
| ⑬ | 案内状 | 10月に対象生成、11月に郵送。一括差込印刷 |
| ⑭ | 郵送料 | 寺院負担。祈願料に含む。送料の列は持たない |
| ⑮ | 翌年度の案内停止 | 明確な理由のみで停止。未申込は外さず要確認 |
| ⑯ | トリガー所有 | 年間法会受付管理と同じ管理用アカウント |
| ⑰ | 枠の対象日・時間帯 | **1/1〜1/31、9:00〜16:00** |
| ⑱ | 1枠の上限 | **人数 50 名・組数 3 組**（超過は要確認、登録は止めない） |
| ⑲ | 未申込要確認年数 | **3 年** |
| ⑳ | 御札の種類 | **外札・内札**（＋新春一般用に `一般札` を1種置く） |

### ⑳の補足

第5回で選ばれたのは「外札・内札（前札）」のみ。新春一般（五千円〜三万円）の御札種別が
未定義になるため、`98` に **`一般札`** を追加する。
木札・紙札・角札・交通安全札は沖縄の実績にのみ現れ、久留米の資料には出てこなかったため入れない。
必要になれば職員が `98` に追記できる。

### 96_フォーム受信

`受信ID／発生日時／フォームID／回答ID／回答日時／回答者メール／処理結果／エラー内容／回答内容（原文）／反映先申込ID／最終記録`

- **受信したら真っ先にここへ原文を保存**してから台帳へ反映する。
- 処理に失敗しても原文は残る。回答IDで再処理できる。

## 8. 状態の遷移

```
案内状態    未準備 → 案内予定 → 印刷済 → 郵送済／メール済／手渡し済
                                        └→ 返戻 →（住所確認）→ 再送 or 案内不要
返答状態    未回答 → 申込予定 → 申込済
                  └→ 辞退（理由を 90/91 へ反映）
                  └→ 連絡待ち → 要確認
申込状態    下書き → 受付中 → 日時調整中 → 確定 → 完了
                                          └→ 取消／重複／テスト（集計から除外）
実施状況    予定 → 実施済／中止
入金状態    未入金 → 一部入金 → 入金済
                              └→ 過入金 → 要確認 → 返金
                    免除
```

`取消`／`重複`／`テスト` は、読上げ一覧・枠割付表・準備一覧・入金確認・集計から除外する。

## 10. Apps Script の構成

```
00_定数.gs      シート名・列見出し・状態リスト。列番号は見出し名から解決する
01_共通.gs      ID採番・ロック・空き行確保・正規化・キャッシュ・ログ
02_受付入力.gs   02_受付入力 の画面制御と登録処理
03_案内対象.gs   92 の生成・差込データ出力・案内状態の一括更新
04_祈願予定.gs   読上げ順の引き継ぎ・枠の上限チェック・03 の再構築
05_入金.gs      95 の upsert・93 への集計・05_入金確認 の更新
06_フォーム受信.gs フォーム送信ハンドラ・96 への原文保存・二重取込防止
07_移行.gs      97_移行作業 への書き出しと反映（管理者用）
08_診断.gs      設定状態の確認・トリガーの診断と復旧（管理者用）
```

### 設計上の決まり

- **固定列番号に依存しない。** 1行目の見出し名から列を解決し、`00_定数.gs` に見出しを定義する。
- **年度・料金・時間枠・フォームID・外部ファイルIDをコードへ埋め込まない。** すべて `99_設定` から読む。
- **読み書きは一括。** `getValues()`／`setValues()` で範囲をまとめる。1行ずつのループで台帳を読み直さない。
- **`onOpen` はメニュー表示と受付画面の更新だけ。** シート構成の修復・全件再集計はしない。
- **`onEdit` で全件再集計しない。** 編集された行に関係する範囲だけを更新する。
- **設定と直近履歴は実行中だけキャッシュする。** 書き換えたらリセットする。
- **新しい内容を作ってから書き換え、余った旧行だけ消す。** 途中エラーでデータが消えないようにする。

### メニュー

日常（`新春祈願受付`）：

1. 受付入力の内容を登録
2. 年度別案内対象を作成
3. 案内状の差込データを出力
4. 設定状態を確認

管理者用（Apps Script エディタから実行、メニューに出さない）：

- `repairShinsunFormTriggers` — フォーム送信トリガーの復旧
- `importLegacyShinsunData` — 旧データを `97_移行作業` へ書き出す
- `rebuildDerivedColumns` — 自動列の再計算

## 13. 移行

### 移行元

| 移行元 | 件数 | 移行先 |
|---|---|---|
| 前札祈願者マスター(R2) | 約170 | `90`／`91`＋`92`(R2)＋`93`(R2) |
| 元朝前札読み上げ 2023／2024／2025 | 各約175 | `92`（各年度） |
| R7新春一般祈願郵送者名簿 | 1 | `90`＋`92`(R7) |
| 令和三年祈願者名簿 | 少数 | `90` |
| 沖縄 新春祈願管理（最新） | — | **移行しない** |

### 手順

1. 元ファイルは**一切変更しない**。読み取り専用で `97_移行作業` へ書き出す。
2. `97` には**元ファイル名と元の行番号**を付ける。
3. 職員が `97` で分類する。分類が必要なのは次の項目。
   - **個人か会社か**（前札マスター(R2) は混在）
   - 略称にない自由記述の願意（`社員安全`／関係者の健康／CD売上ヒット成就）
   - 同姓同名・表記ゆれの名寄せ
   - 連名・合算の金額按分（井町家31万／時里組15万）
   - 奉納品の文章の構造化（お酒5本／御神酒4本／特大矢×3）
   - 宛名注記（案内状は後援会長宛 など）
4. 分類後、`97` から `90`／`91`／`92`／`93`／`94` へ反映する。
5. **件数照合**：移行元の行数・移行後の行数・除外した行数と理由を `99` のログに残す。
6. 過年度の `92` は**参照専用**。案内状態は `（過去実績）` で固定し、再生成の対象にしない。

### 自動変換するもの

| 変換 | 内容 |
|---|---|
| 願意の略称→正式名称 | 事業→事業繁栄／工事→工事安全／繁栄→繁栄隆昌／心願→心願成就／交通→交通安全／家内→家内安全／健康→健康成就／商売→商売繁昌／海上→海上安全／厄除→厄除／災難→災難消除／諸願成就→諸願成就 |
| 札送りの記号→受渡方法 | 〇→郵送／持参→持参／来山→来山／預→預かり／持帰→持帰 |
| 読上げ名簿→年度別申込有無 | 名前があれば `申込あり`、読上げ順は列の並び順 |

`大漁`・`社員安全`・`作業安全`・`金運`・`芸事`・`意識回復` などは `98` の38願意にない。
`98` へ追加するか `その他`＋備考にするかは職員が判断する。

### 過年度に入る項目

`92` の過年度行に入るのは **年度／氏名／読上げ順／申込あり** の4項目のみ。
祈願日時・祈願料・入金は入らない（R2 のみ前札マスターから補える）。
R9 の案内状「昨年申込済み／新規」の出し分けには、**2025年の読上げ名簿**を前年実績として使う。
