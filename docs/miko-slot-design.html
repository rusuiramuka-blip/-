枠を先に作り、巫女が自分で入る
シフト運用の設計

「仮枠を先に置く」「本人が入る」「足りないところが一目でわかる」「実働が違ったら直せる」の 4 つを、いまのシートの上に無理なく載せる形でまとめました。07_必要人数 と 04_日別30分配置 に必要な部品がすでに揃っているので、作るのは 枠の自動生成・巫女用ウェブアプリ・期間サマリ・当日ボタン の 4 つです。

誰が何を見るか

「運用が簡単」は、機能を減らすことではなく 役割ごとに見る場所を 1 つに絞る ことで作ります。いま現場メニューは 9 項目、管理メニューは 11 項目あり、どちらも全員に見えています。

巫女アルバイト

スマホのウェブアプリだけ。空き枠を見て「入る」を押す。スプレッドシートは一切開かない（開かせない）。

現場担当シフト・当日

02B_募集状況で足りない日を見て枠を足す／募集を出す。04_日別30分配置で当日の並びを見る。02A_当日勤怠で実働を確定する。メニューは 4 つ。

管理者給与

給与ファイルで 承認 → 締め → 支給 → 受領。現場ファイルは見なくてよい。メニューは 5 つ。

① 枠を先に作る

07_必要人数 から 02_シフト入力 へ、担当者を空欄にした行を必要人数ぶん自動生成するメニューを作ります。これが枠先行方式の入口です。

メニュー「期間の枠を作成」

// 07_必要人数（状態="使用"）× 対象期間の各日 → 02_シフト入力
生成する列  B 日付 / F 出勤 / G 退勤 / H 休憩分 / J 主配置 / K 賃金区分 / N 状態="下書き"
空けておく列 D 担当者   ← ここに巫女が自分で入る
自動で埋まる列 A 勤務ID / C シフト名 / E スタッフID / I 実働予定 / L 昼食 / M 夕食
                P 警告 / S 開始日時 / T 終了日時 / U 深夜予定h

対象日の決め方（既存の 04_日別30分配置 と同じ考え方）
  その日を指定した行があれば → その行の必要人数
  なければ                  → 対象日が空欄の行（期間共通）の必要人数

再実行しても増えない
  「日付 × 配置 × 時間帯」で既存の枠を数え、不足ぶんだけ追加する

深夜枠は日跨ぎです。23:00 → 翌8:00 なので退勤 < 出勤になりますが、既存の T 終了日時 の式が IF($G<=$F,1,0) で翌日補正しているため、そのまま正しく動きます。休憩分だけは深夜枠の実態に合わせて既定値を決めてください。

行数の拡張が前提条件になります。42名/日 なので、正月三が日前後の 6 日間でも 252 行、対象期間の 34 日全部なら 1,428 行。02_シフト入力 は現在 5〜504 行の 500 行しかなく、12 日分で満杯です。枠先行にするなら先に 3,000 行程度へ拡張し、数式の参照範囲（$B$5:$B$504 など）も同時に伸ばしてください。

② 巫女が自分で入る

スプレッドシートを巫女に共有してはいけません。01_スタッフ には全員の区分・18歳判定・襦袢の貸与状況が並び、02_シフト入力 は誰でも他人の行を消せます。閲覧権限だけでも個人情報が全部見えます。

代わりに Apps Script のウェブアプリ（実行者＝管理者、アクセス＝Googleアカウント所有者全員）を 1 枚作ります。巫女はスマホで URL を開くだけで、スプレッドシートには一切触れません。書き込みは管理者の権限で行われるので、共有設定を変える必要もありません。

画面

  • 日付を選ぶ → その日の 早番 / 中番 / 深夜 が残り人数つきで並ぶ（「早番 あと8人」）
  • 「入る」を押す → 確認 → 完了。自分が入っている枠には「入っています／取り消す」が出る
  • 足りない日は 赤、あと少しは 黄 で表示。02B_募集状況（③）と同じ色にすると「赤いところに入ると助かる」が言葉なしで伝わります

本人の特定

01_スタッフ に メールアドレス列（I列）を追加し、ウェブアプリ側で Session.getActiveUser().getEmail() と突き合わせます。登録のないアドレスは弾く。合言葉方式より安全で、巫女側の手間もありません。

安全弁 — 自己申込にするなら、ここが本体です

  • 18歳未満は深夜枠を選べない01_スタッフ!F が「18歳以上」でなければ深夜枠を非表示にし、送信時にもう一度弾く。労基法61条。登録36名のうち11名が該当するので、人手で見張るのは現実的ではありません。
  • 時間が重なる枠は取れない開始日時・終了日時の重なりで判定。これで「同日複数勤務」の警告が 本当に重なっているときだけ出るようになり、早番＋遅番の分割勤務が毎回警告になる現状の問題も同時に解決します。
  • 定員に達したら締切LockService.getScriptLock() の内側で残数を数え直してから書き込む。同時に押しても定員は超えません。ロックを取らずに書くと、正月の申込ラッシュで必ず定員オーバーが起きます。
  • 直前の取消は本人にさせない前日18時以降は「取り消す」を出さず、現場への連絡を促す。取消希望は 09_申込 に記録だけ残す。
  • 1人あたりの上限（任意）連続勤務日数や合計時間の上限を _設定 に置き、超える申込を止める。07_スタッフ・賃金 の源泉区分が「未判定」の人を止める、といった使い方もできます。

申込をいったん保留して管理者が確定する「承認モード」にしたい場合も、09_申込 に「受付」で止めて別メニューで確定するだけです。切替は _設定 のフラグ 1 つで足ります。経験者の配分を調整したい日だけ承認モード、というのが現実的だと思います。

③ 一目で足りないところがわかる

不足を出す計算は すでに 04_日別30分配置 の 61〜73 行にあります。「割当済／枠／必要」を出して 不足 / 未割当 / 適正 / 余剰 に振り分ける、よくできた式です。問題は見え方のほうです。

  • 1 日ずつしか見えない。B2 で日付を切り替える作りなので、34 日間のどこが足りないかは 34 回切り替えないとわかりません
  • 13配置 × 48列 = 624 セルを目で追うことになる。1/1 だけで「不足」が 93 セル出ています
  • 52枠の表示上限があり（A58 の警告）、42名/日 に加えて交代が入る 1/1 は超えます

新シート 02B_募集状況 — 期間ぜんぶを 1 画面に

行＝日付、列＝時間帯。セルは「あと何人」。34行 × 5列なのでスクロールなしで収まります。実データを置くとこう見えます。

日付必要枠確定あと状態
12/29 (火)4234348枠を8つ追加
12/30 (水)4234348枠を8つ追加
12/31 (木)424949+7必要より7枠多い
1/1 (金)42212121半分しかない
1/2 (土)420042枠が未作成
1/3 (日) 〜 1/31420042/日枠が未作成（29日分）
不足が大きい あと少し 充足 必要より多い

必要・枠・確定はいずれも現在のシートの実数です（時間帯ごとの内訳は枠を生成した時点で決まります）。この 1 枚があれば「1/1 が半分しか埋まっていない」「1/2 以降は枠すら作っていない」が最初の 3 秒でわかります。いまは同じことを知るのに 04_日別30分配置 の日付を 34 回切り替える必要があります。

セルの式（考え方は既存の B61 と同じ）

=LET(
  d, $A6, band, B$5,
  // その日を指定した行があればそれを、なければ期間共通を使う
  spec,    SUMPRODUCT(N(必要!$B=d), N(必要!$E=band), N(必要!$K="使用"), N(必要!$H)),
  hasSpec, SUMPRODUCT(N(必要!$B=d), N(必要!$E=band), N(必要!$K="使用")),
  gen,     SUMPRODUCT(N(必要!$B=""), N(必要!$E=band), N(必要!$K="使用"), N(必要!$H)),
  need, IF(hasSpec>0, spec, gen),
  // 担当者が決まっている枠を数える
  filled, COUNTIFS(シフト!$B, d, シフト!$V, band, シフト!$D, "<>", シフト!$N, "<>取消"),
  need - filled)

前提：02_シフト入力 に「時間帯」列（V列）を足す必要があります。いま C シフト名 は出勤時刻から 早番／中番／遅番 を出しますが、07_必要人数 の呼び名は 早番／中番／深夜。この 2 つが食い違っているため、時間帯で突き合わせる集計がそのままではできません。07_必要人数 側の呼び名に統一し、V列で開始・終了時刻から時間帯名を判定してください。

④ 実働が予定と違ったとき

02A_当日勤怠 は予定と実績を分けて持ち、差異区分・実働差分・変更理由・元勤務ID まで用意されています。設計は正しいので、足りないのは操作を 1 タップにするボタンです。00_ホーム にも「メニューの『予定どおりを反映』が最短です」と書かれていますが、そのメニューはまだ存在しません。

実際に起きたこと操作起きること
予定どおり働いた予定どおりを反映実出勤・実退勤・実休憩に予定をコピー、実績状態＝勤務済。複数行まとめて
遅刻・早退した実出勤／実退勤を直すだけ差異区分・実働差分（M列）が自動で出る
休憩が違った実休憩を直すだけ同上
当日欠勤欠勤にする実績状態＝欠勤確定、変更理由を必須入力、給与は0
前日までに取消の連絡枠を再募集する担当者だけを外す。枠は残るので 02B に「あと1人」として戻り、他の巫女が入れる
代わりの人が入った担当者を交代元の行を取消、新しい勤務IDの行に元勤務IDを記録
途中で売場が変わった03_配置変更 に追記04_日別30分配置 に反映される（既存機能）

枠先行でいちばん大事な区別です。欠員が出たとき 02_シフト入力 の行を「取消」にしてはいけません。行ごと取消にすると枠そのものが消えて募集に出なくなります。外すのは担当者（D列）だけ。00_ホーム の未割当枠の式が 状態<>取消 を条件にしているのは、まさにこの区別のためです。

実績が固まったら 02A_当日勤怠 → 給与ファイルの 01_勤怠承認 へ送信します。この送信処理は前回の診断の A-2 で挙げたとおりまだ実装されていません。ここが繋がって初めて、現場の 1 タップが給与まで通ります。

進め方

前回の診断で挙げた A-1（スタッフID の列違い） と A-3（襦袢台帳の列違い） は定数の付け替えだけなので、どの段階よりも先に直しておくと以降が楽になります。

段階やることこの時点でできるようになること
0前回診断の A-1・A-3、行数の拡張送信したデータが給与側で正しく紐づく
1V列（時間帯）追加、呼び名の統一、02B_募集状況34日分の不足が1画面で見える
2メニュー「期間の枠を作成」仮枠が並ぶ。手で138行入れる作業がなくなる
3ウェブアプリ（18歳未満の深夜ブロック・重複判定・ロック）巫女が自分で入れる。02B の赤が減っていく
4当日ボタン 4つ ＋ 実績を給与へ送信現場の1タップが給与まで通る
500_ホームを「今日やること」に、メニューを役割別に整理毎日開く場所が1つになる

段階 1 と 2 だけでも、いまの「1/2 以降は枠すら作っていない」状態は解消できます。ウェブアプリ（段階 3）は作る量が最も多いので、正月に間に合わないようなら、段階 2 までを先に入れて枠の一覧を印刷して手挙げしてもらい、現場担当が入力する運用でも回ります。その場合でも 02B があるかないかで、募集のかけ方が変わります。

数字の出どころ：07_必要人数（使用23定義・合計42名/日）、01_スタッフ（36名・18歳未満11名）、02_シフト入力（日付入り138行・担当者なし0行・12/29〜1/1）、_設定（対象期間 2026/12/29〜2027/1/31）、00_ホーム および 04_日別30分配置 の集計式。いずれも現在のファイルから直接読み取った値です。
