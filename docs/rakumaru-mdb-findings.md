# 楽まる寺務のバックアップ（.mdb）を読んだ結果

2026-09-09。`20260722…DataBackUp.mdb`（8.4MB／JET4／Microsoft Access）を
読み取りだけで確認した。ファイルは変更していない。

## 1. 読めるか

読める。Linux の `mdbtools`（`mdb-schema` / `mdb-export`）で全テーブルを
CSV に出せる。テーブル名が日本語なので `LC_ALL=C.UTF-8` が要る。

**ただし Apps Script は .mdb を直接開けない。**
取り込むには、いったん CSV／スプレッドシートへ変換する必要がある。

**すべて .mdb にある。**

: 年度／祈願区分ID／施主CD／整理番号／**金額計**／**入金日**／**入金額**／入金区分／
  参列／**参列日**／参列時／参列分／**参加人数**／**護摩**／**神酒渡し**／**酒奉納数**／
  **お守取置**／**安全旗渡し**／領収書有無／**領収書宛名**／送付済み／
  **確定・保留・辞退**／次回案内状文書／新春札送り状文書／新春料御礼状文書

祈願者（`TD400s`）
: 申込番号／施主家族CD／**願意1〜10**／**祈願料**／会社名／役職／敬称／氏名／
  フリガナ／〒／住所／家名／**札持帰り**／電話／携帯／FAX／**対応**／**祈願代表者**／
  **前札_会社名・前札_役職・前札_氏名**／**内札_会社名・内札_役職・内札_氏名**

**外札（前札）と内札が最初から別々の列になっている。**
段階3で「外札と内札の見分けがわからない」として保留した点が、そのまま解決する。

## 5. 年度

**令和5年（2023）から令和9年（2027）までの5年分**がある。
移行で取り込めたのは R8 の1年分だけだったので、4年分が増える。

R9（2027）は前札144件が既に入っている。楽まる寺務側で翌年度へ繰り越した分。
段階4で作った前札143件とほぼ一致する（差1件）。

## 6. 願意

延べ 6,004 件、**255種類**。1件の祈願者に最大8個入っている。

`TM400_願意マスタ` は23件しかなく、実データの255種類のうち230種類が
マスタにない（「古賀家先祖」「部員の健康」「仕事運向上」など）。
つまり**願意は自由入力**で、マスタは入力候補にすぎない。

`98_マスター` の願意38件も同じ扱いにする必要がある。
入力規則は「候補は出すが、ほかの値も入れられる」（`setAllowInvalid(true)`）にする。

表記ゆれもある。`商売繫盛(353)` と `商売繁昌(193)`、
`繫栄隆昌(118)` と `繁栄隆昌(87)` は同じ願意の別表記。

## 7. 祈願料

`TD400s.祈願料` に入っている。50,000×795／5,000×778／10,000×747／
25,000×196／15,000×123／20,000×48／30,000×48／0×123。

申込側の `金額計` は R8 前札で 50,000×88・0×42 と欠けがあるので、
**金額は祈願者側の `祈願料` を合計して出すほうが確実。**

## 8. 注意点

- backup は **2026-07-22 時点**。楽まる寺務は今も使われているので、
  R9 の分はこれより増えている可能性がある。
- 施主マスタ 989件は祈願以外（回忌・管理費・永代経など）も含む全体の名簿。
  祈願の申込に出てくる施主CDだけを見ないと、案内対象が広がりすぎる。
- 区分9と区分16が何かは、寺院に確認しないとわからない。
