# 正月のお守り — 現場用画面（取り置き・お渡し・残数）

沖縄・久留米の御守在庫ファイルにある正月の作業を、スマホ・タブレットから
1つの画面で行うためのウェブアプリ。考え方は `docs/omamori-shogatsu-redesign.md`。

| タブ | 使う人・場面 | 書き込む先 |
|---|---|---|
| ① 受付 | 受付担当。お名前と商品・数量を入れて登録 | 取り置き一覧に1商品1行で追加 |
| ② お渡し | 名前・電話・受付番号でさがし、「取り分けた」「お渡しした」を押す | 取り置き一覧の K・N・O・P 列 |
| 取り分け表 | 準備担当。まだ取り分けていない数を商品ごとに合計 | 読むだけ |
| ③ 残りを数える | 正月明け。場所ごとに残数を入れる | 正月の準備シートの U・V・W 列 |

正月の **予定数・準備完了** は、これまでどおり管理者が PC で正月の準備シートに入力する。

## ファイル

```
Code.gs          サーバー側（シートの読み書き）
index.html       画面
appsscript.json  タイムゾーン・権限・ウェブアプリ設定
```

## 導入（1回だけ・管理者）

1. **在庫ファイルのコピーを取る**（ファイル > コピーを作成）。
2. https://script.google.com で **新しいプロジェクト** を作る。
   在庫ファイルの「拡張機能 > Apps Script」には **貼らない**
   （在庫側の `onOpen` などと混ざらないよう、別プロジェクトにする）。
3. `Code.gs` と `index.html`（HTML ファイルとして追加し、名前は `index`）を貼る。
   「プロジェクトの設定」で「appsscript.json をエディタで表示」をオンにし、`appsscript.json` も貼る。
4. 「デプロイ > 新しいデプロイ > ウェブアプリ」
   - 次のユーザーとして実行: **ウェブアプリにアクセスしているユーザー**
   - アクセスできるユーザー: **Google アカウントを持つ全員**
   - 実行するのは「開いた人」なので、**在庫ファイルの編集権限がない人は何も見られない**
     （お名前・電話番号の保護はファイルの共有設定がそのまま効く）。
5. 表示された URL の末尾に拠点を付けたものが現場用の URL。
   - 沖縄: `…/exec?site=okinawa`
   - 久留米: `…/exec?site=kurume`
6. 各ファイルの `00_入口` の「取り置きを受け付ける」行の C 列に、その URL を
   `=HYPERLINK("…/exec?site=okinawa","開く")` のように入れる。
   スマホのホーム画面に追加しておくと、正月中はアプリのように開ける。
7. **沖縄の `08-1_取り置き受付` を非表示にする**（右クリック > シートを非表示）。
   受付はこの画面に移るので、セルに書く受付票は使わない。削除はしない。
8. 職員ごとに一度だけ、初回に開いたとき Google の許可画面が出るので「許可」を押す。

## 動作確認（本番前に必ず）

1. `Code.gs` 冒頭の `SITES.okinawa.ssId` をコピーしたファイルの ID に一時的に替えて、
   `?site=okinawa` で開く。
2. 2商品で受付 → 取り置き一覧に2行・同じ受付番号で入り、A・I・L・M 列の式が効いているか。
3. 正月の準備シートの「うち取り置き中」（沖縄 Q列）が増えるか。
4. ② で「取り分けた」→「代金を受け取って お渡しした」→ お支払い・状況・お渡し日が変わるか。
   「ひとつ前に戻す」で戻るか。
5. ③ で本堂に数を入れて保存 → U 列に入るか。3か所そろうと「正月にお渡しした数」が出るか。
6. ID を本番に戻してデプロイを更新（「デプロイを管理 > 編集 > 新バージョン」。URL は変わらない）。

## 守っていること

- 列の並びは両拠点で同じ（A〜S）。開くたびに見出しを照合し、並びが違えば書かずに止まる。
- 書き込みは `LockService` で1人ずつ。受付は画面ごとの重複防止キー（S列）で二重登録しない。
- 残数の保存は、変えた行だけを差し替える（同じ列を別の人が数えていても消さない）。
- 受付番号は `沖27-001` のような短い番号（拠点・正月の年・連番）。袋に書きやすくするため。
  既存の受付番号（久留米の `KRM-…` など）はそのまま使える。

## 注意

- 久留米の正月シートは `取り置き確保数（Q）` を `正月確保数（R）` に **足す** 古い計算のまま。
  沖縄は「取り置きは準備数の内訳で、足さない」に直してある。久留米も沖縄の考え方に
  合わせるのがおすすめ（`docs/omamori-shogatsu-redesign.md` の「久留米の計算」）。
- 久留米の正月シート Q列の式は取り置き一覧の **689行目まで** しか数えない。
  それを超えると画面に警告が出るので、式の範囲を広げる。
- 在庫ファイル側の「正月のお守り」メニューの ② 受付（沖縄）は、この画面と同じ一覧へ書くので
  併用しても壊れないが、現場には **この画面だけ** を案内する。
