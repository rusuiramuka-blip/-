# 巫女管理・新設計（スタンドアロン版ウェブアプリ）

Drive の Apps Script プロジェクト「巫女管理_新設計_独立確認_20261018」のソース。
`genba/`・`kyuyo/`（スプレッドシートに付けるスクリプト）とは別の、台帳1つとウェブアプリ1つの構成。

| ファイル | 内容 |
|---|---|
| `Code.gs` | 台帳の読み書き、権限、配置・勤怠・面接・メールの保存、点検 |
| `Payroll.gs` | 分単位の給与計算、丙欄の源泉税、金種、精算・受領・差額訂正 |
| `Setup.gs` | 初期台帳、控え、次年度準備と切替、フォーム受信、旧台帳からの移行 |
| `MaintenanceSecurity.gs` | 保守トリガーの移行と、トリガーからの実行の確認 |
| `index.html` | 職員用の画面 |
| `test/run.js` | 計算部分のテスト（`node apps-script/shinsekkei/test/run.js`） |

## 反映のしかた

このフォルダの `.gs` と `index.html` を、Apps Script エディタの同名ファイルに貼り替えて保存する。
ウェブアプリは「デプロイを管理 → 編集 → 新しいバージョン」で更新する（URL は変わらない）。

## 今回の修正（2026-11-08）

1. **点検・給与計算の高速化**：分ごとのループの中で毎回していた日付変換・最低賃金の検索・休日の判定を、
   暦日ごとに1回だけにした（`dayInfo_`）。判定と金額は変更前と同じ（無作為の1,300件で一致を確認）。
   80人×10勤務で、点検 2.1秒→0.14秒、給与計算 1.4秒→0.14秒（Node での計測）。
2. **1,000行の上限を解消**：保存先の行が足りなければ `ensureRows_` が行を足し、2行目の書式・入力規則と
   `配置!実休憩分` の式を新しい行へ引き継ぐ。保護（`protectPaid_`）と入力規則も実際の行数まで広げる。
3. **次年度の台帳への切替**：エディタから次の順に実行する。
   1. `prepareNextYear` — 期間を1年ずらした新しい台帳を作り、保護をかける。まだ切り替えない
   2. 新しい台帳の `設定`・`売場`・`勤務帯` を確認する
   3. `switchLedger` — 画面と自動処理の参照先を新しい台帳へ。前の台帳IDは `前年度台帳ID` に残る
   4. 応募フォームを使う場合は、新しい台帳の設定に `応募フォームID` と質問の対応を入れて `connectReception`
4. **分割勤務への誤った注意をやめた**：「前の勤務からの休息が短くなっています」は、
   勤務日と勤務日の間（間隔が `継続勤務間隔分` 以上）だけで判定する。

## 反映後に確認すること

- 行の追加：`勤務希望` などが1,000行を超えたあとに保存できること。人事担当のアカウントでも1回確かめる
  （保護された範囲があるシートへの行の追加）
- 切替後、翌朝の控え（`dailyBackupTrigger_`）が新しい台帳で作られていること（実行数の画面）
- 切替後に応募フォームの設定を入れるまでは、応募トリガーがエラーを出す（回答はフォーム側に残る）
