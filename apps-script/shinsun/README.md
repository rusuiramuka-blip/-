## 構成

```
apps-script/shinsun/
  00_定数.gs      シート名・見出し名・98/99 の初期値・移行元の定義。列番号は持たない
  01_共通.gs      見出し名からの列解決・ID採番・ロック・設定/マスタ読取・ログ
  07_移行.gs      段階2。97_移行作業 の作成と旧データの書き出し（管理者用）

```

段階4以降で `02_受付入力.gs` `03_案内対象.gs` `04_祈願予定.gs` `05_入金.gs`
`06_フォーム受信.gs` `08_診断.gs` を足す。

## 導入手順

### 1. コードを貼る

1. 上記スプレッドシートを **rusuiramuka@gmail.com** で開く。
2. 「拡張機能 > Apps Script」を開く。
3. 既定の `コード.gs` を削除し、`00_定数.gs` `01_共通.gs` `09_初期設定.gs` の3ファイルを
   **同じ名前で**作って貼り付ける。
4. 「プロジェクトの設定」で `appsscript.json` を表示し、`"timeZone": "Asia/Tokyo"` を確認する。

### 2. 初期設定を1回だけ実行

1. エディタの関数一覧から **`setupShinsunStage1`** を選んで実行する。
2. 初回は権限の承認を求められる。**rusuiramuka@gmail.com** で承認する。
3. 完了すると5シートが作られ、シートの並びが整う。

`setupShinsunStage1` は**何度実行しても既存データを消さない**。
`98_マスター` と `99_設定` は、既に行があれば**不足分だけを足す**（値の上書きはしない）。

### 3. 確認

スプレッドシートを開き直し、メニュー「**新春祈願受付 > 設定状態を確認**」を実行する。
「段階1の設定は正常です。」と出れば完了。

段階1のトリガーは **フォーム送信0・編集0・変更0** が正常。
段階8で フォーム送信2・編集1・変更1 になる。

## 段階1でできること

| できること | 場所 |
|---|---|
| 信者様の登録（氏名を入れると `P-0001` が自動採番される） | `90_信者様マスター` |
| 会社の登録（会社名を入れると `C-0001` と拠点 `-01` が自動採番される） | `91_会社マスター` |
| 同じ会社の支店を足す（会社IDを同じにして拠点IDを空欄にすると `-02` が付く） | `91_会社マスター` |
| 選択肢の追加（区分・値・表示順・有効を入れる） | `98_マスター` |
| 年度・枠・上限などの変更 | `99_設定・操作ログ`（非表示。右クリック > シートを再表示） |

### 自動で起きること

- **ID採番**：氏名・会社名を入れた行に ID が付く。`LockService` で採番と書込みを保護しているので、
  2人が同時に入力しても ID は重複しない。
- **既定値**：敬称・案内方法・翌年度案内状態が空欄なら埋まる（個人は `様`／会社は `御中`、いずれも `郵送`・`継続`）。
- **同姓同名の通知**：同じ氏名が既にあると通知が出る。**登録は止めない。**
  別人ならそのまま登録し、同一人物なら既存行を更新する。
- **停止理由の督促**：翌年度案内状態を `継続` 以外にすると、案内停止理由の欄が赤くなり通知が出る。
  理由のない案内停止は行わない。

## 段階1では「まだない」もの

`92_年度別案内対象` 以降がないため、次の列は空欄のまま。段階4で埋まる。

- `直近3年の申込` / `最終申込年度` / `連続未申込年数`

## 設計上の決まり（段階2以降も守る）

- **固定列番号を使わない。** 列は `headerMap_()` で見出し名から解決する。
- **年度・料金・時間枠・フォームID・アカウントをコードに書かない。** すべて `99_設定` から読む。
- **ID採番は書込みまで含めてロックの中で行う。**
- **読み書きは一括。** 1行ずつのループで台帳を読み直さない。
- **`onOpen` はメニュー表示だけ。** シート構成の修復・全件再集計はしない。
- **`onEdit` で全件再集計しない。** 編集された行に関係する範囲だけを更新する。
- **新しい内容を作ってから書き換え、余った旧行だけ消す。**
- **自動メールは `99_設定` の「自動メール有効」が FALSE の間は送らない。** 段階9の承認まで FALSE のまま。

# 段階2｜旧データの書き出し

`97_移行作業` を作り、旧データを **元ファイル名・元の行と列を付けて** 書き出す。
この段階では `90` / `91` / `92` へは**何も書かない**。反映は段階3で職員が分類してから行う。

## 0. 移行元を Google スプレッドシートへ変換する

Apps Script は `.xlsx` を直接開けない。ドライブで変換したコピーを作り、そのIDを `99_設定` へ入れる。

各ファイルをドライブで開き、`ファイル > Google スプレッドシートとして保存`。

## 1. 実行

1. `07_移行.gs` を貼り、`setupShinsunStage2` を実行 → `97_移行作業` ができる
2. `99_設定` の「移行元_〜」4行へ、変換したコピーのIDを入れる
3. `importLegacyShinsunData` を実行 → 件数照合が出る
4. `checkShinsunMigration` で分類の進み具合を確認

## 2. 何が入るか

| 列 | 誰が入れる |
|---|---|
| `移行ID`〜`生データ` | 取り込みが入れる。元の行が丸ごと `生データ` に残る |
| `区分` `確定名称` `対象ID` `処理` | **職員が入力する**（黄色い列） |
| `反映状態` `反映日時` `要確認` | 段階3の反映処理が使う |

`移行ID` は元ファイルの位置から作るので、**取り込み直しても同じ行には同じIDが付く**。
職員が入力した `区分` `確定名称` `対象ID` `処理` は取り込み直しても引き継がれる。

## 3. 取り込みの仕方（元資料の形に合わせている）

- **元朝前札読み上げ**：シート名を年度、1セル1名として読む。
  読上げ順は `99_設定` の「読上げ順の方向」に従って仮に付ける（既定は列方向）。
  印刷の並びと違えば設定を「行方向」に変えて取り込み直す。
- **前札祈願者マスター(R2)**：見出し行が資料の途中で何度も現れるため、
  **直近の見出しから列を決める**。願意・奉納品だけの行は直前の記録の続きとして結合し、
  `要確認` に「続き行を結合（n行）」と残す。
- **一般の名簿**：氏名・〒・住所などの見出しを見つけて読む。

## 4. 段階2でやらないこと

- `90` / `91` / `92` への書き込み（段階3）
- 個人か会社かの判定（職員が `区分` に入力する）
- 連名・合算の金額按分、奉納品の文章の構造化、宛名注記の切り分け（職員が判断する）
